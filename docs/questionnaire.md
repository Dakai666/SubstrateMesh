# 使用者畫像收集問卷

用途：**收集**，不是考試。把這份問卷交給不同的 AI（ChatGPT、Gemini、Claude App、opencode、hermes、loom…），
讓它們各自說出對使用者的了解，再匯入 SubstrateMesh，由 Keeper 對帳、擴充與糾錯。

## 設計原則

1. **盲測**：不先提供任何既有畫像，避免 AI 附和或錨定。
2. **允許「不知道」**：空白比編造有價值。沒有記憶功能的 AI 應直接說明，不要硬答。
3. **區分口吻**：使用者說過的（stated）／從互動中觀察到的（observed）／推測的（inferred）。
4. **要證據**：盡量附上使用者原話與大約的時間或情境。
5. **反巴納姆**：放諸四海皆準的描述（「重視品質」「喜歡深度思考」）沒有資訊量，要求具體化。
6. **收集 AI 自己的觀點**：它觀察到的張力、矛盾、變化，以及它想問使用者的問題。

## 使用方式

1. 在目標 AI **開一個新對話**，貼上下方「問卷本文」整段。
   - 有長期記憶功能的平台（例如 ChatGPT 記憶、Claude 的專案記憶），請確認記憶已開啟。
   - 若某個 AI 同時有多個專案或工作區，建議在主要使用的那個裡面回答。
2. 把回覆全文存成文字檔，例如 `replies/chatgpt.md`。
3. 匯入：

   ```bash
   substrate import replies/chatgpt.md --source chatgpt
   ```

   - 回覆全文存為原始紀錄：`raw/imports/<日期>-<來源>.md`（含張力與提問，供 Keeper 參考）。
   - 每一項 `items` 轉為一筆記憶 PR，提案者即該 AI。
   - 第三方轉述一律**不建議進入憲法層**；推測的信心度上限為 0.6；當前焦點自動設 30 天 TTL。
   - 與既有待審提案相同的主張會自動併為佐證；與既有知識相同的轉為強化。
4. 各 AI 都匯入後，請 Keeper 做一次對帳：共識、分歧、與現有畫像衝突之處、新發現。

## 問卷本文（整段複製貼上）

````text
我正在整理一份「AI 對我的了解」的個人檔案，會把不同 AI 的回答彙整、交叉比對，再由我親自糾錯。
請根據你對我的所有記憶與過往互動，誠實回答下列問題。

【回答規則——請務必遵守】
1. 只寫你真的有依據的內容。不知道就寫不知道，或整段留空。空白比猜測有價值。
2. 不要寫放諸四海皆準的描述（例如「你重視品質」「你喜歡深度思考」）。每一條都要具體到能區分「我」和「一般人」，而且有可能被我否定。
3. 每一條請標示口吻：
   - stated：我明確說過的
   - observed：你從我的行為中觀察到的
   - inferred：你自己的推測
4. 盡量附上我說過的原話（逐字最好），以及大約的時間或情境。
5. 不要討好我，也不要為了顯得了解我而湊數。如果你對我的印象有負面或讓我不舒服的部分，一樣請誠實寫出。
6. 如果你沒有長期記憶，只能依據這次對話，請在 memory_access 說明，然後 items 可以留空。

【請涵蓋以下面向（沒有依據的面向直接略過）】
A. 身分與背景：職業、專長、正在學的東西
B. 能力地圖：哪些領域我是專家（可以省略解釋）、哪些熟悉但不深入、哪些陌生
C. 溝通偏好：語言、語氣、格式、長度，以及在不同情境下的差異
D. 協作方式：我希望 AI 什麼時候自己決定、什麼時候先問；我怎麼下指令、怎麼給回饋
E. 反感的 AI 行為：我糾正過你什麼、對什麼不耐煩
F. 決策風格與價值取捨：我怎麼做決定、在什麼之間權衡
G. 思想與世界觀：哲學、科學、靈性或其他影響我的思想
H. 技術環境：常用工具、語言、平台、正在做的專案
I. 當前焦點：最近在忙、在想、在煩惱的事
J. 原則與紅線：我明確表示絕對不能做的事

【另外請提供】
- 你的平台記憶原文：如果你有儲存關於我的記憶，請逐條原樣列出，不要改寫。
- 張力與矛盾：你注意到我身上看似矛盾、或因情境而異的地方。
- 變化：你觀察到我的偏好或想法隨時間改變的地方。
- 你想問我的問題：為了更了解我，你最想確認的 3 件事。

【輸出格式】
先用一兩句話說明你的記憶來源與可靠程度，然後用一個 yaml 程式碼區塊輸出（欄位名稱保持英文，內容用繁體中文）：

```yaml
respondent: 你的名稱與版本
memory_access: 你有哪些關於我的記憶來源（長期記憶／專案檔案／只有本次對話）
platform_memory: |
  （平台記憶原文，逐條原樣列出；沒有就留空）
items:
  - claim: 一句話的具體描述
    kind: preference   # preference 偏好 | fact 事實 | principle 原則 | lesson 教訓 | focus 當前焦點
    voice: stated      # stated | observed | inferred
    confidence: 0.8    # 0 到 1
    domain: communication   # 對應的面向，例如 identity、communication、collaboration、worldview、tech
    contexts: [code-review] # 適用情境，可省略
    evidence:
      - quote: 我說過的原話
        when: 大約時間或情境
    rationale: 你為什麼這樣認為
tensions:
  - 看似矛盾或因情境而異的地方
changes:
  - 隨時間改變的地方
questions:
  - 你最想問我的問題
```
````

## 選用：第二輪「糾錯」

盲測匯入並對帳後，可以把**名片等級**的畫像摘要（`views/` 或 agent 連線時收到的核心摘要）貼給同一個 AI，請它指出：

- 哪些和它的觀察不一致（附依據）
- 哪些它認為過度概括、需要加上情境
- 哪些重要面向完全沒有被記錄

第二輪的回覆同樣可用 `substrate import` 匯入。這一輪帶有錨定效應，Keeper 審查時應給予較低權重。
