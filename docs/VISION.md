# 願景

## 問題：上下文的所有權錯置

與 AI agent 的互動中，使用者的偏好、習慣、要求與期望全部是**碎片化**的：

- 散落在 `CLAUDE.md`、ChatGPT Memory、Cursor Rules、各 agent 框架各自的 memory 模組裡。
- 這些記憶綁在**工具**上，而不是綁在**人**上；換工具，AI 就重新不認識你。
- 最有價值的訊號——你每一次對 agent 的**糾正**——只活在單次對話裡，隨即消失。

## 核心信念

1. **模型是可替換的零件，上下文才是資產。**
   Claude、GPT、Gemini 都只是 runtime。SubstrateMesh 本身也不得依賴任何特定模型——包括 Keeper。
2. **知識是活的：攝入 → 消化 → 鞏固 → 遺忘。**
   每條知識都有來源、信心度、適用條件與時效；會被強化、修正、晉升、降級、封存。
3. **原始紀錄是唯一真相，其餘皆可重建。**
   十年後演算法換了，只要原始事件還在，就能重新提煉。
4. **誰有權定義「我是誰」，必須由使用者掌控。**
   Agent 只能提案，Keeper 負責守門，使用者是最終權威。
5. **格式要比程式長壽。**
   純文字 + git。程式可以重寫十次，記憶不動。

## 與「Markdown + Obsidian 個人庫」的差異

| | Obsidian 式個人庫 | SubstrateMesh |
|---|---|---|
| 誰寫入 | 人 | 人 + 所有 agent（經由提案） |
| 誰讀取 | 人 | 主要是 agent；人負責審閱 |
| 知識狀態 | 寫下即靜止 | 強化、衰減、修正、合併 |
| 真實性 | 文件寫什麼就是什麼 | 有出處、信心度、時效 |
| 輸出 | 筆記本身 | 依任務動態組裝的上下文 |

## 範圍

- **優先**：「關於我」——身分、自主邊界、偏好、反模式、決策風格、能力地圖、原則與目標。
- **逐步擴展**：專案工作區、跨專案的經驗教訓。

## 刻意不做的事

- **不做 Observer。** 不去「靜默監聽」任何對話；agent 應該自己學會提交。
- **不做 Orchestrator。** 任務分派與 agent 協作是 agent 框架的職責。
  SubstrateMesh 只當**基質**，不當指揮官；真有需要，另外串一個 agent 即可。
- **不先做龐大的知識圖譜 ontology。**
- **不先做 UI。** 第一個使用者是 agent，不是人。
